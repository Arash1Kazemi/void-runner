# Stage 0 – feasibility test (not the game)

Checks the hardware design inside Wokwi before any game code is written:

- **432 single LEDs** – a 16 × 24 game screen plus 3 status bars, wired as one row/column matrix
  (27 row lines on pins 22–48, 16 column lines on A0–A15). LED bodies are dark; only the light
  is coloured, so lit LEDs stand out even zoomed out. The wiring inside the panel is hidden.
- **4 × 4 push-button keypad** on pins 14–21 – each button also reacts to a PC keyboard key
- **3 buzzers** on pins 5, 6 and 11, each driven by its own hardware timer

`diagram.json` and `stage0/pins.h` are generated by `tools/gen_circuit.py` – don't edit them by hand.
Wokwi's checker warns that the dark LED colours are "invalid"; they render correctly
(see `tools/led_style_preview.html`).

## Run it

**VS Code:** File → Open Folder → `tests/stage0`, then `F1` → **Wokwi: Start Simulator**.

### Before pressing keys (important)
1. **Click once on an empty spot of the circuit** after every Start/Restart. VS Code puts the
   keyboard focus on the "Wokwi Terminal"; keys then go to the Serial port instead of the buttons.
   If that happens the Serial Monitor prints *"keys are going to the Serial terminal"*.
2. **Use the English keyboard layout.** Wokwi matches the typed character, so with the Persian
   layout R sends "ق" and no button reacts.
3. Check keys with the Serial lines (`[KEY] ... DOWN R`), not only by eye.

## Keys

| Key | Does |
|---|---|
| E | next test pattern: test card → all LEDs on → checkerboard → one LED at a time |
| M | sound: three buzzers (chords) → off → one buzzer (melody) |
| B | scan method: port writes (default) ↔ `digitalWrite` |
| F | refresh rate: 71 → 50 → 35 pictures per second |
| X | screen scanning on/off |

## Measured (Wokwi cloud simulator, Wokwi CLI)

| Setting | Simulation speed |
|---|---|
| Test card, three buzzers | ~94 % |
| All 432 LEDs lit, three buzzers | ~91 % |

The buzzer pins were recorded with Wokwi's logic analyzer: all three play the right notes
(within 1 %). The automated check `scenarios/stage0_check.yaml` passes (keys one and two at
once, stray Serial letters, screen as text). Serial test commands now need a `!` prefix (`!p`, `!d` …).
