# VOID RUNNER – design spec (version 1.0, full game)

A vertical space shooter on an Arduino Mega with a screen built from single LEDs, a keypad
built from single push buttons, and four buzzers. Simulation only (Wokwi for VS Code and
wokwi.com). Three phases, each with its own enemies, space rocks and a boss.

Pictures of the real screens (rendered from the running code): `docs/media/` –
`screens_menus.png`, `screens_game.png`, `screens_texts.png` (every message page),
`screens_ledtest.png` and animations
`logo.gif`, `phase1.gif`, `warden.gif`, `king.gif`, `victory.gif`.

---

## 1. Hardware (course parts only: Mega, LEDs, push buttons, buzzers – no libraries)

| Part | Count | Connection |
|---|---|---|
| Arduino Mega 2560 | 1 | – |
| Single LEDs (`wokwi-led`), one matrix | 432 | 16 × 24 game screen + 3 status bars of 16. 27 row lines (anodes) on pins 22–45 and 47–49, 16 column lines (cathodes) on A0–A15 |
| Push buttons (`wokwi-pushbutton`), 4 × 4 matrix | 16 | rows on 18–21, columns on 14–17 |
| Buzzers (`wokwi-buzzer`) | 4 | pins 5, 6, 11, 46 (Timer3, Timer4, Timer1, Timer5 outputs) |

- 55 of the Mega's 68 usable pins (27 + 16 + 8 + 4), each header used for one job: double header = LED rows,
  analog header = LED columns, communication header = keypad, PWM header = buzzers. The fourth
  buzzer is on pin 46 of the double header, because that is Timer5's output (the LED row that
  was there moved to pin 49); it is the last free timer – Timer0 runs `millis()`, Timer2 the screen.
- `diagram.json` and `pins.h` are generated by `tools/gen_circuit.py`, so circuit and code
  always agree. The wiring inside the LED panel is hidden; every wire to the Mega is shown.

**LED colours** come from the layout, not from code: each LED has a fixed colour. LED bodies
are dark and only the light is coloured, so a lit LED stands out clearly. Colour bands, like
the colour film strips on the 1978 Space Invaders cabinet:

| Area | Colour | Use in the game |
|---|---|---|
| Status bar 1 | red | phase progress → boss health |
| Status bar 2 | yellow | ammo (blinks when low) |
| Status bar 3 | green | lives (one block of 3 LEDs per life) |
| Game rows 0–5 | red | where enemies and bosses enter, "WARN", "ZONE" |
| Game rows 6–17 | white | open space, message pages |
| Game rows 18–23 | green | the player's zone |

**LED brightness:** each LED is lit only 1/27 of the time (one row at a time). Wokwi shows
an LED's brightness as (share of time on)^(1/gamma), averaged over 100 ms – measured on
wokwi.com: with the default gamma 2.8 a lit LED showed at only 32 % and the game was hard to
see on the grey canvas. Every LED has `gamma` = 30 → 90 %, which is what a real multiplexed
display does by driving each LED harder during its short time slot. Every LED also has
`fps` = 300: Wokwi averages over 8 updates, so the window is 27 ms instead of 100 ms and
moving things stay sharp. Everything that blinks stays on/off for at least 160 ms.

**Text:** never scrolls. Scrolling letters smeared into a white block in Wokwi (user test,
22 Oct). Messages are still **pages** of short words (up to 4 small letters per line, 0.9 s
each), with big digits and symbols where a word is not needed (`tools/text_preview.html`
compares the styles).

## 2. Controls

The keypad buttons are labelled like keyboard keys and also react to the PC keyboard
(click an empty spot of the circuit first; use the English keyboard layout).

```
┌───┬───┬───┬───┐
│ Q │ W │ E │ R │    W A S D  move
├───┼───┼───┼───┤    R        fire (hold = auto-fire) · OK in menus
│ A │ S │ D │ F │    Q        back (in the game: pause)
├───┼───┼───┼───┤    P        pause / continue
│ Z │ X │ C │ V │    M        sound on/off (any screen, saved)
├───┼───┼───┼───┤    B        brightness 100 / 50 / 20 % (any screen, saved)
│ P │ M │ B │ H │    E F Z X C V H  spare
└───┴───┴───┴───┘
```

**Firing (agreed):** press R → one bullet; keep holding → one more every 0.2 s (a chirp when
auto-fire starts, the ship's nose blinks); release → stop. A move key stops firing; to fire
again press R again. While R is held the ship does not glide. The newest key wins.
**Moving:** tap = one pixel; hold = after 0.17 s the ship glides (BOLT 14 pixels/s). The
ship can use rows 9–23. Every enemy is slower than every ship – except the HUNTER boss.

## 3. Screens

```
Start-up logo + melody (5.6 s, any key skips)
        ↓
Title  ── VOID sign lit, ships flying past, banner pages "PUSH", big R, "TO", "PLAY"
        │  untouched for 20 s → DEMO: the autopilot plays, any key → back to the title
        ↓ R
Menu   ── PLAY · SHIP · OPTS · BEST   (W/S choose, R open, Q back to the title)
        ├─ SHIP (hangar): A/D choose BOLT / DART / TWIN, shown 3× big; the status bars
        │                  show its speed / ammo / fire power; R = take it, Q = back
        ├─ OPTS: LITE (brightness) · SND (sound) · DIFF (EASY / NORM / HARD) · TEST (LED test)
        │        W/S item, A/D or R change, page dots at the bottom; saved in EEPROM
        └─ BEST: high score, then how far it got (ZONE 1–3, or WIN) and its difficulty
PLAY → Phase 1 → Boss 1 → Phase 2 → Boss 2 → Phase 3 → Boss 3 → VICTORY (fireworks)
Pause (P or Q): score, a big pause sign, pages "P:GO" / "Q:EX"
GAME OVER: score (blinks for a new record), best score; R or Q → menu
LED TEST: all LEDs, row sweep, column sweep, checkerboard, with rising beeps
```

## 4. Gameplay

| Topic | Rule |
|---|---|
| Lives | EASY 4, NORMAL 3, HARD 3 (max 4). Hit → explosion, screen shake, 2 s blinking shield. +1 life after each phase; extra-life pickups. |
| Ammo | Per ship (60 / 40 / 80). Every phase starts full. Ammo crates fall from the top: fly into them (+20 / 15 / 12 by difficulty). At 5 or less: warning beep and the yellow bar blinks; a crate is always sent then. Empty → dry click. |
| Enemies | All slow; at most 4 / 5 / 6 on the screen at once (phase 1 / 2 / 3), so the 16 × 24 screen stays readable. They shoot only from rows 0–9, so no bullet starts right next to the ship. |
| Space rocks | Fall and drift sideways; a big rock takes 3 hits and breaks into 2 small ones. Hurt on contact. |
| Explosions | Only the bosses and the player's ship explode into flying pixels. Enemies, rocks and mines just vanish (with a boom), and a hit enemy disappears for 120 ms – flying debris on 16 × 24 LEDs looked like bullets. No background stars in the game for the same reason. |
| Pickups | Ammo crate (box) and extra life (blinking plus). Cruisers drop a life; other enemies sometimes drop ammo. |
| Bosses | One per phase; health on the red status bar (it drops with every hit); they blink before the HUNTER's dive, at the VOID KING's change and while burning; their bullets and helpers vanish when they die. |
| Score | Drone 10, weaver 15, miner 20, cruiser 40, rocks 5/10, mine 2, pickup 5, bosses 200/300/500, phase bonus 100 × phase. High score + zone reached + difficulty in EEPROM. A higher score takes the record; an equal score only on a harder difficulty. |

**Difficulty** (OPTS → DIFF): EASY = 4 lives, enemies fire 1.5× slower, bosses 80 % health,
crates +20. NORMAL = 3 lives, 100 %, +15. HARD = 3 lives, enemies fire 1.33× faster, bosses
130 % health, crates +12.

## 5. Phases

Each phase: pages "ZONE" + big phase number, the phase name, "GO!" with a fanfare → waves
from a spawn list (`levels.h`) → "WARN" + a blinking warning sign + siren while the red bar
charges → boss with its own music → boss explodes → pages "ZONE DONE", bonus "PTS",
"LIFE UP". Victory: fireworks + pages "YOU WIN!", "VOID SAFE", score.

| Phase | Enemies | Boss |
|---|---|---|
| 1 – ROCK BELT (asteroids) | Drone (sinks, shoots straight down), many rocks | **WARDEN** – wide (10 × 4), slides along the top, 3-way spread, drops rocks; below half health faster with a 5-way spread |
| 2 – DEEP MIST (a nebula) | Weaver (zig-zags), Mine-layer (crosses the top, drops blinking mines that can be shot), drones | **HUNTER** – small and FAST: dashes to a new spot, fires an aimed pair; every 7 s blinks and dives at the player |
| 3 – The Void | Cruiser (5 hits, stops near the top, aimed shots), everything else, rock showers | **VOID KING** – huge (12 × 5), 5-way spread, calls in drones; at half health the eye opens (roar, shake): aimed triple volleys and rock rain |

Boss health: WARDEN 24, HUNTER 22, VOID KING 40 (× difficulty).

## 7. Logo – VOID RUNNER (`docs/media/logo.gif`)

"VOID" is a vertical sign of bold 10 × 5 letters: V in the red band, O and I in the white band,
D in the green band. The picture runs on the song's own clock, so every movement lands on a note.

| Time | Picture | Sound (3 of the buzzers) |
|---|---|---|
| 0.0 – 1.2 s | warp: star streaks speed up | rising whoosh + low A2 drone |
| 1.2 – 2.0 s | the ship rises and brakes | braking notes E4 C4 A3 |
| 2.0 – 2.4 s | the ship shoots up and out | quick rising glide |
| 2.4 – 3.6 s | V, O, I, D light up one by one, flickering on; drones fly past in the margins | A4 C5 E5 A5, crackle on each flicker |
| 3.6 – 4.8 s | "RUNNER" crosses on a dark ribbon, towed by the ship | melody + harmony + bass line |
| 4.8 – 5.6 s | whole screen flashes, then the sign glows | A-minor chord |

The status bars fill during the logo like a start-up progress bar.

## 8. Sound (four buzzers)

| Buzzer | Pin / timer | Job |
|---|---|---|
| 1 | 5 / Timer3 | lead guitar (melody) |
| 2 | 6 / Timer4 | bass |
| 3 | 11 / Timer1 | every sound effect and menu sound; music only in the short jingles |
| 4 | 46 / Timer5 | rhythm guitar: a fifth above the bass (bass + rhythm = a power chord) |

- Each buzzer is driven by its own hardware timer, so four notes can play at once (Arduino's
  `tone()` can only play one) and a note costs no processor time.
- In-game music: original metal tracks, written in a short notation in
  `tools/compose_music.py` (which writes the note lists into `tunes.h`; all voices of a song
  have the same length so the loop stays in time). Listen: `docs/media/music/*.wav`.
  - ROCK BELT: thrash, E minor, galloping bass, about 190 BPM (loop 10.2 s)
  - DEEP MIST: slow, heavy drop-D chugs, D minor (loop 12.8 s)
  - THE VOID: syncopated groove with a catchy lead, E minor (loop 9.6 s)
  - Boss: tremolo-picked bass, chromatic lead (loop 4.5 s)
- Other music: start-up melody (logo, synced to the picture), phase fanfare, phase clear,
  victory, game over.
- Effects on buzzer 3, with priorities so an important sound is never cut by a small one:
  shot, auto-fire chirp, empty click, hit, explosion, big explosion, player hit, pickup,
  extra life, low ammo, warning siren, boss roar, LED-test sweep. Explosions are noise
  (a random frequency every 6 ms), the rest are slides between two frequencies.

## 9. How conflicts are prevented (measured)

- **Screen:** a Timer2 interrupt lights one LED row at a time, 71 times per second for the
  whole screen. Port writes (`PORTF`/`PORTK`) for the columns: 3 % of the processor
  (`digitalWrite` would take 35 %).
- **Simulation speed:** timers run on slow clocks (÷256) and unused timers are stopped –
  Wokwi spends time on every timer count. Measured: ~93 % during the logo, ~91 % with every
  LED lit.
- **Nothing blocks:** no `delay()` in the game; a picture every 20 ms, each part does one
  small step. The game has its own clock that stops while paused.
- **Memory:** fixed-size arrays only (no `malloc`). 32.6 KB of 248 KB flash, 2.0 KB of 8 KB
  RAM. Fonts, art, music and spawn lists are in flash.
- **Fairness:** at most 4–6 enemies at once; enemies don't shoot from close range; a crate
  always comes when ammo runs low; every phase is checked to be winnable (section 10).

## 10. Tests

| Test | How | Result |
|---|---|---|
| Stage 0 / 1 | Wokwi scenarios (`tests/scenarios/`) press the real buttons, check Serial and the screen as text | passed |
| Full game in Wokwi | `tests/scenarios/playthrough.yaml` (shield + autopilot + fast mode) | reached the victory screen (before the final balance changes; then the free plan's CLI minutes ran out) |
| Controls | `tests/host/controls.txt` – tap, glide, row limit, single shot, auto-fire rate, move-cancels-fire, no glide while firing | pass |
| Every screen | `tests/host/screens.txt` – logo skip, title, menu, hangar, options, LED test, best, pause, game over + new record, global keys, power cycle (EEPROM), demo | pass |
| Whole game | `tests/host/playthrough.txt` – all phases, bosses, Void King form 2, victory | pass |
| Balance | `run_tests.py --balance`: autopilot without shield, reacting only every 250 ms (roughly a human), 12 games per level | EASY 11/12 won, NORMAL 7/12, HARD 4/12 |

The `tests/host` tests compile the real game code on the PC with a stand-in for Arduino
(`tests/host/Arduino.h`) and run a whole game in well under a second – no Wokwi minutes.

Serial test commands (start with `!`): `!d` screen as text, `!s` game state + CPU time per
picture, `!1`–`!3` start at a phase, `!b` skip to the boss, `!w` boss loses its health,
`!i` shield, `!x` autopilot, `!f` fast mode (8 steps per picture), `!k` lose the last life.
