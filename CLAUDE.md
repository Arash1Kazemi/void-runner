# VOID RUNNER – project notes for Claude

University project (Digital Systems 2 / Microprocessors, "Project 1"): a device on an Arduino
Mega with an LED-matrix display, a matrix keypad and a buzzer. We build a vertical space
shooter, **VOID RUNNER**. Simulation only (Wokwi for VS Code with a Community license, and
wokwi.com) – there is no real hardware. Design spec: `docs/SPEC.md`. User-facing run guide:
`README.md`.

## Course rules (from the teacher – do not break)
- Parts: **only** Arduino Mega, single LEDs (`wokwi-led`), single push buttons
  (`wokwi-pushbutton`), buzzers (`wokwi-buzzer`). Any number of them. No prebuilt modules
  (no WS2812/NeoPixel matrix, no MAX7219, no membrane keypad), no resistors needed.
- **No libraries** (no Adafruit NeoPixel, Keypad, etc.). Arduino core functions taught in the
  course are welcome: `pinMode`, `digitalWrite`, `digitalRead`, `millis`, `delay`, `Serial`.
  Register-level code (ports, timers, interrupts) is allowed as "advanced programming" – use it
  only where measured necessary, and comment it so the student can explain it.
- Grading is part by part (logo + welcome music, keypad control, the device itself, LED
  layout/colours, hardware orderliness, code orderliness/comments, documentation,
  presentation). A broken part loses its points, so reliability beats features.

## Hardware (all generated – never hand-edit `diagram.json` or `void_runner/pins.h`)
- `tools/gen_circuit.py <project_dir> <sketch_dir>` generates `diagram.json`, `pins.h` and
  `circuit_preview.png`, and checks every wire (must print `wiring errors: 0`,
  `visible wire crossings: 0`).
- 432 LEDs = 16 × 24 game screen + 3 status bars (16 each), one matrix: 27 rows (anodes,
  pins 22–48), 16 columns (cathodes, A0–A15; column x = pin Ax = PORTF/PORTK bit). Keypad
  4 × 4: rows 18–21, columns 14–17. Buzzers on 5, 6, 11 (Timer3/4/1 OCnA).
- LED colours: dark hex body + coloured `lightColor` (zones red/white/green, status bars
  red/yellow/green). `wokwi-cli lint` shows 432 "invalid color" warnings for the hex bodies –
  expected and harmless (they render correctly).
- LED `gamma` = 30 (`LED_GAMMA` in gen_circuit.py). Measured on wokwi.com: brightness shown
  = duty^(1/gamma), averaged over 100 ms (fps 80 × 8 subframes); our duty is 1/27 →
  gamma 2.8 = 32 % (user: "hard to see"), 30 = 90 %. Side effects: blinks must be ≥ 100 ms
  on/off (use `frameNo & 8`), "dim on alternate frames" no longer looks dim, and PWM
  dimming (B key / LITE) is barely visible in Wokwi (90 → 85 %). The off-LED look (grey
  leads, white highlights, body colour at 65 % opacity) is fixed by Wokwi's LED drawing.
- Keypad labels are keyboard letters (Q W E R / A S D F / Z X C V / P M B H), `key` attr set.

## Code (`void_runner/`, header-per-module, one translation unit)
`config.h` settings, Screen enum, difficulty tables · `display.h` scan ISR, drawing, text,
message pages, numbers, status bars · `input.h` keypad scan/debounce · `sound.h` 3-voice buzzer
engine + SFX engine (voice 3, priorities) · `tunes.h` songs + effects · `storage.h` settings
+ best score in EEPROM (registers) · `art.h` pixel art · `font.h` (generated by
`tools/gen_font.py`) · `logo.h` · `title.h` · `menu.h` · `world.h` all entity pools
(player, shots, enemies, pickups, particles, stars, boss) · `player.h` key rules, fire,
hits · `enemies.h` enemy/rock behaviour · `boss.h` WARDEN/HUNTER/VOID KING · `levels.h`
spawn lists per phase (PROGMEM) · `game.h` phase stages, collisions, status bars ·
`autopilot.h` test/demo bot · `screens.h` hangar, options, best, pause, game over, victory,
LED test · `void_runner.ino` screen state machine, Serial test commands, demo.
Game logic runs on `gameMs` (20 ms steps, stops on pause); sound uses `millis()`.

Keys: W A S D move, R fire/OK, Q back, P pause, M mute (global), B brightness (global).

## Hard-won technical facts (measured – keep them)
- Screen scan: Timer2 CTC /256, one row per interrupt, ~71 Hz full refresh; columns via
  `PORTF`/`PORTK` (≈3 % CPU; `digitalWrite` would be ≈35 %). Draw into `frame[]`, then
  `present()` copies it with interrupts off.
- Wokwi spends time on every timer count: run timers on slow clocks (buzzers /256, scan /256)
  and stop unused timers (1, 3, 4, 5) at startup. Buzzer clock /8 made the sim ~2.5× slower.
- Buzzer timers: clear `TCCRnA` / write the mode bits **before** `OCRnA` – in Arduino's default
  PWM mode OCR writes are buffered and the first note is lost.
- Notes up to ~C7 are accurate at /256. Arduino `tone()` is not used (one voice only).
- No `delay()` in game code; everything advances per 20 ms frame.
- Serial test commands need a `!` prefix (`!d` = dump screen as text); stray letters print a
  hint, because in VS Code keyboard focus often lands in the Wokwi Terminal. Full list in
  the .ino (`!s !1-3 !b !w !i !x !f !k`).
- User feedback 2026-10-22: scrolling text was unreadable (100 ms averaging smeared it) →
  all messages are still pages (`drawPage`, `pageAt`, PAGE_MS 900 in display.h), max 4 small
  letters per line, big digit / warning sign / pause sign; LED `fps` = 300 (27 ms window).
  Phase names: ROCK BELT, DEEP MIST, THE VOID.
- User feedback 2026-10-22: explosion debris for normal enemies was confusing → particles
  only for bosses and the player's ship; no background stars in the game.
- Balance (found with the autopilot): slow enemies pile up, so each phase caps enemies on
  screen (4/5/6); enemies only shoot from rows 0–9 (point-blank shots were undodgeable).
  With a 250 ms-reaction bot: EASY 11/12, NORMAL 7/12, HARD 4/12 wins. Re-run after tuning.
- Sizes: 31.2 KB flash, 1.9 KB RAM. CPU time per picture on the AVR is not measured yet
  (Wokwi quota ran out) – `!s` prints `frame work us=`.

## Build, run, test
- Compile: `build.cmd` (or `arduino-cli compile --fqbn arduino:avr:mega --warnings all
  --output-dir build void_runner`). arduino-cli: `%LOCALAPPDATA%\Programs\arduino-cli\`.
- Wokwi CLI: `%LOCALAPPDATA%\Programs\wokwi-cli\wokwi-cli.exe`. Token is in the user's Windows
  env `WOKWI_CLI_TOKEN` (User scope) – load it inside the command
  (`[Environment]::GetEnvironmentVariable('WOKWI_CLI_TOKEN','User')`), **never print it**.
  Free plan: 50 simulation minutes / 30 days – keep runs short.
- **PC tests (preferred, free):** `python tests/host/run_tests.py [--balance]` builds
  `tests/host/sim.cpp` (real game code + `tests/host/Arduino.h` stand-in: registers as
  variables, EEPROM array, simulated clock, keypad via `digitalRead`, avr-libc `random`) with
  MSYS2 g++ (`C:\msys64\ucrt64\bin`, link `-static`) and runs the `tests/host/*.txt` scripts
  (`run/down/up/tap/send/until/dump/record/sound/reset/seed/times`). A whole game < 1 s.
  Debug the game by recording frames (`record`) and rendering them.
- Wokwi scenarios: `tests/scenarios/stage1_check.yaml`, `playthrough.yaml` (press real
  buttons with `set-control … pressed`, check Serial). **The free plan's CLI minutes were
  used up on 2026-10-21** (quota is per 30 days); the user's VS Code extension still works.
  `wait-serial` only matches lines printed after the previous match (order matters).
- `tools/render_dumps.py <log> <png|gif> [frames|ms]` turns dumps into pictures / GIFs in the
  real LED colours (GIF needs Pillow: run with plain `python`, not `python -I`).
- All text files use LF line endings. Python on this PC writes CRLF in text mode – always
  pass `newline='\n'` (or write bytes) when a script edits project files.
- Shell gotchas here: Python's default encoding is cp1252 (pass `encoding='utf-8'`);
  backslashes in commands sent through Bash get eaten (`\n` in sed/Python became real
  newlines) – use the Edit tool for C escapes and Windows paths; the path has a space
  (`Semesterr 7`).
- Sound can be verified with a logic analyzer copy of the diagram + `--vcd-file`.
- Two Wokwi configs exist: root `wokwi.toml` (the game) and `tests/stage0/wokwi.toml` (Stage 0
  test). In VS Code the user must pick the root one (`F1` → Wokwi: Select Config File) and
  click the circuit before using the keyboard (English layout).
- The user tests in VS Code; Wokwi's MCP server (`wokwi-cli mcp`) can start sims, read serial
  and press buttons, but cannot screenshot the whole circuit.
